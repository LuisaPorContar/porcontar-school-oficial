01 · El punto de partida

¿Qué es Claude y cuántos tipos hay?

Claude es el asistente de inteligencia artificial de Anthropic: conversa, escribe, analiza documentos y ejecuta tareas cuando se conecta a herramientas externas. No es un solo producto. Según el tipo de entregable que necesites, existe una versión distinta pensada para eso.

2023

Anthropic lanza la primera versión del chat al público.

2024

Llegan los modelos Haiku, Sonnet y Opus — cada uno para un nivel distinto de tarea.

2025 – 2026

Nace el resto del ecosistema: Cowork, Claude Code y Claude Agents.

Los modelos: no todos piensan igual de rápido

Haiku

Pensado para tareas rápidas y consultas simples. El más ágil de los tres.

Sonnet

Entiende contextos complejos, analiza documentos, escribe contenido y programa. El equilibrio para el día a día.

Opus

El más potente. Para lo difícil: análisis profundos, problemas matemáticos complejos, razonamientos largos donde no se puede perder en el camino. Más lento, pero más capaz.

Fable 5

Tiene sentido cuando el trabajo es largo y complicado: una migración de código grande, un análisis financiero con muchas variables — algo que normalmente tomaría días armar.

Cinco formas de trabajar con Claude

Claude Chat

Conversaciones inteligentes. Vive en la nube: le subís archivos puntuales, procesa y te devuelve un resultado que descargas.

Claude Cowork

Vive en tu computador y opera sobre él. Le das acceso a una carpeta entera, no archivos sueltos, y trabaja ahí directamente.

Claude Code

Desarrollo potenciado. Escribe y edita código, lleva el historial de cambios, trabaja directo dentro de tu proyecto.

Claude Design

Diseño inteligente. Prototipos, mockups y presentaciones hablando con Claude: le describís lo que quieres y lo va ajustando con tú.

Claude Agents

Automatización inteligente. Agentes conectados a tus herramientas — vía MCP, Composio o Make — corriendo en segundo plano.

02 · Vocabulario base

Los ocho términos que vas a escuchar todo el tiempo

Antes de entrar en técnicas o herramientas, conviene tener clara la diferencia entre estas ocho palabras. Se usan todo el tiempo, y confundirlas hace que las explicaciones de cualquier tutorial suenen más complicadas de lo que son.

Artefacto El entregable

Un documento, código o diseño que Claude genera en un panel aparte de la conversación, no mezclado con el texto del chat. Queda editable: pides cambios puntuales, lo descargas o seguís trabajando sobre él sin perder el hilo. Sirve para reportes, páginas web, gráficos, cualquier cosa que valga la pena conservar como archivo propio.

Proyecto El espacio

Un espacio de trabajo donde agrupas conversaciones, archivos e instrucciones que comparten un mismo contexto: todo lo de un cliente, o toda una línea de contenido. Cada conversación dentro del proyecto ya tiene acceso a esa información, sin que la repitas cada vez que abrís un chat nuevo.

Plugin El paquete

Un paquete de herramientas, comandos y skills que le agrega a Claude capacidades para un tipo de trabajo específico. Instalas uno y Claude puede, por ejemplo, seguir el playbook de ventas de tu empresa o aplicar tu manual de estilo sin que se lo expliques cada vez.

Conector El puente

Conecta a Claude con una app externa —Gmail, Notion, Miro, tu CRM— para que pueda leer y actuar sobre información real, no solo hablar del tema en abstracto. Cada conector expone un conjunto de acciones: buscar, crear, actualizar. Más abajo está el catálogo completo.

API El puente

El puente de comunicación entre dos programas. Piénsalo como el mesero de un restaurante: tú no entras a la cocina a preparar la comida, le haces el pedido al mesero, él lo lleva y te trae el plato. Los conectores y los MCP existen porque las apps exponen una API que Claude puede usar.

MCP Model Context Protocol

El idioma común que le permite a Claude conectarse con otras apps y usarlas, sin que tú tengas que aprender el idioma de cada una. Es como viajar por cinco países con un traductor universal: cada app sigue hablando el suyo, tú hablas uno solo y el MCP se encarga de traducir.

Prompt La instrucción

La instrucción que le das a Claude para que haga algo. Puede ser una pregunta suelta o una instrucción estructurada con rol, contexto y ejemplos. Cuanto más clara la instrucción, mejor el resultado — de eso trata buena parte de esta guía.

Skill El proceso guardado

Instrucciones guardadas que Claude consulta antes de hacer una tarea repetitiva, para seguir siempre el mismo proceso y el mismo formato sin que se lo expliques de nuevo. Un skill es a Claude lo que un manual de procedimiento es a un empleado nuevo.

03 · Memoria de Claude y Skills

Qué es un archivo .md y qué es un memory.md

Esta es la base de todo lo que sigue: si Claude va a recordar quién eres y cómo trabajas, tiene que guardarlo en algún lado. Ese lugar es un archivo de texto con extensión .md.

¿Qué es un archivo .md?＋

Un .md es un archivo de texto plano en formato Markdown — liviano, sin la complejidad de un Word — que usa símbolos simples (#, *, -) para marcar títulos, listas y negritas. Claude lo lee sin ningún problema, y es el formato que usa la mayoría de los sistemas de skills y de memoria porque ocupa poco espacio y se edita a mano en cualquier editor de texto, incluso desde el celular.

¿Qué es un memory.md o CLAUDE.md?＋

Es el archivo .md donde guardas el contexto fijo que quieres que Claude recuerde de una persona, una empresa o un proyecto: quién es, cómo trabaja, qué le gusta y qué no, qué herramientas usa, qué información nunca hay que guardar. Claude lo lee al empezar cada tarea nueva, así no repetís lo mismo en cada conversación. En Claude Cowork, este archivo suele vivir en la raíz de la carpeta de trabajo junto con un CLAUDE.md que le dice al modelo cómo comportarse y a qué skill recurrir según el encargo.

¿Cómo armo un Skill?+

Un skill se construye con tres partes. Si a alguna le falta detalle, Claude lo va a usar mal o directamente no lo va a activar cuando corresponde.

NombreCómo se va a llamar tu skill — la forma en la que lo vas a reconocer entre los demás.
DescripciónDice qué hace y, sobre todo, cuándo usarla. Es lo que Claude lee para decidir si la activa en una tarea puntual.
InstruccionesEl proceso paso a paso, las reglas fijas, ejemplos de entrada y salida, y los archivos de referencia o plantillas que necesite consultar.
04 · Atajo

Si ya venís hablando con la IA, que sea ella la que arme tu memory.md

No hace falta llenar el archivo a mano desde cero. Si ya tienes historial de conversación con Claude — ya sabe cómo trabajas, qué proyectos llevas, qué te gusta y qué no — pégale este prompt en Claude Cowork y deja que sea la misma IA la que te entreviste y arme el sistema completo: carpetas, CLAUDE.md, memoria.md y skills.

prompt-configurar-cowork.txt
Quiero que me ayudes a crear un sistema de trabajo personalizado dentro de la carpeta que tienes seleccionada. El objetivo es que Claude Cowork entienda quién soy, cómo trabajo, qué tareas repito y cómo debe organizar y ejecutar mis encargos sin que tenga que explicárselo todo en cada conversación. Antes de crear o modificar ningún archivo, entrevístame para reunir la información necesaria. REGLAS PARA LA ENTREVISTA 1. Hazme una sola pregunta cada vez y espera mi respuesta antes de continuar. 2. Utiliza un máximo de ocho preguntas principales. 3. Pide ejemplos concretos cuando una respuesta sea demasiado genérica. 4. Asegúrate de entender, como mínimo: - Quién soy y a qué me dedico. - Qué proyectos o áreas de trabajo quiero gestionar. - Qué tareas realizo de forma recurrente. - Qué archivos, datos o fuentes utilizo habitualmente. - Qué entregables quiero obtener y en qué formatos. - Qué tono, estilo y nivel de detalle prefiero. - Qué acciones requieren siempre mi aprobación. - Qué preferencias o aprendizajes merece la pena conservar. 5. No inventes información ni completes respuestas por tu cuenta. PROPUESTA ANTES DE CREAR EL SISTEMA Cuando termines la entrevista, muéstrame primero una propuesta breve que incluya: - La estructura de carpetas recomendada. - Las instrucciones principales que contendrá CLAUDE.md. - Las preferencias iniciales que contendrá memoria.md. - Las Skills que propones crear y para qué servirá cada una. - Las reglas de seguridad y aprobación. Espera mi confirmación antes de crear o modificar archivos. CREACIÓN DEL SISTEMA Cuando apruebe la propuesta, crea dentro de la carpeta seleccionada: 1. Las carpetas necesarias para organizar mi trabajo. 2. Un archivo llamado exactamente CLAUDE.md en la raíz. 3. Un archivo llamado memoria.md en la raíz. 4. Una carpeta Skills con una subcarpeta para cada proceso recurrente. 5. Dentro de cada subcarpeta de Skills, un archivo llamado SKILL.md. CONTENIDO DE CLAUDE.md Debe incluir de forma clara y concisa: - Quién soy y cuál es el objetivo del espacio de trabajo. - Cómo debe comportarse Claude y cómo debe comunicarse conmigo. - Un mapa de las carpetas y el contenido de cada una. - Dónde debe guardar cada tipo de entregable. - Qué información debe verificar antes de sacar conclusiones. - Qué acciones nunca debe realizar sin mi autorización. - Qué Skill debe cargar para cada tarea recurrente. - La instrucción de leer memoria.md al comenzar cada nueva tarea. - La instrucción de actualizar memoria.md cuando yo diga explícitamente que recuerde una preferencia estable. CONTENIDO DE memoria.md Organízalo en secciones sencillas para guardar: - Preferencias confirmadas. - Proyectos activos y próximos pasos. - Decisiones que no conviene volver a discutir. - Formatos, tono y criterios habituales para los entregables. - Nuevos aprendizajes que yo pida recordar. No guardes contraseñas, datos sensibles, suposiciones ni información temporal que no vaya a ser útil en tareas futuras. CONTENIDO DE LAS SKILLS Crea únicamente Skills para procesos que realmente se repitan. Cada SKILL.md debe indicar: - Cuándo debe utilizarse. - Qué información necesita. - Los pasos exactos que debe seguir. - Cómo debe comprobar el resultado. - Dónde debe guardar el entregable. - Qué acciones requieren aprobación. No cargues todas las Skills en cada tarea. CLAUDE.md debe indicar cuál utilizar dependiendo del encargo. SEGURIDAD - No elimines, muevas, renombres ni sobrescribas archivos existentes sin mi autorización explícita. - Si la carpeta ya contiene información, revísala primero en modo de solo lectura y adapta la propuesta a lo que ya existe. - No envíes mensajes, publiques contenido, realices compras ni ejecutes acciones externas sin mostrarme antes exactamente qué vas a hacer. ENTREGA FINAL Cuando termines, muéstrame: - Los archivos y carpetas que has creado. - Una explicación breve de cómo funciona el sistema. - Tres ejemplos de instrucciones cortas que ya podría utilizar. - Qué partes debería revisar o personalizar con el tiempo. Empieza ahora con la primera pregunta. No hagas todas las preguntas a la vez.
05 · Estructura de un prompt

Las seis partes de un prompt que da resultados consistentes

No hace falta escribir así cada vez que le pides algo simple a Claude. Pero para tareas que importan de verdad — un análisis financiero, un guion, una propuesta de cliente — esta estructura evita que el resultado salga genérico o incompleto en el primer intento.

01

Rol o identidad

¿Quién tiene que ser Claude para responder esto?

Le dices desde qué lugar profesional tiene que responder. Esto le ayuda a enfocar su comportamiento — cambia el vocabulario, el nivel de detalle y los criterios que usa.

«Compórtate como un experto en finanzas.»
02

Contexto y motivación

Los antecedentes del proyecto

Explicas el porqué y el para qué. Sin esto, Claude no sabe si necesitas algo exhaustivo o algo rápido.

«Quiero que generes un análisis financiero con indicadores.»
03

Datos de entrada

La información que tiene que trabajar el modelo

Qué le vas a entregar — un PDF, un Excel, una API. Nómbralo con precisión para que sepa qué esperar antes de empezar.

«Te voy a entregar los estados financieros de los últimos 3 años: 2021, 2022 y 2024.»
04

Datos de salida

El formato en el que quieres recibir el resultado

Un texto largo, un texto corto, una imagen, una tabla. Cuanto más específico seas aquí, menos ajustes vas a pedir después.

«Quiero un análisis con los indicadores más relevantes: retorno a la inversión, gastos, ingresos, etcétera.»
05

Secuencia

El orden de los pasos que tiene que seguir

Explicas el orden exacto que debe seguir para completar la tarea. Le da estructura al razonamiento y evita que salte directo a conclusiones.

«1. Lee los informes. 2. Genera un análisis estratégico. 3. Crea un informe de proyección.»
06

Agrega ejemplos

Ejemplos bien elaborados de cómo quieres el resultado

Opcional, pero es lo que más sube la calidad de la respuesta. Un formato de referencia, un tono, una estructura ya usada antes.

Un informe anterior que te gustó, o el formato exacto de tabla que esperas recibir.

06 · Técnicas de prompting

Diecisiete formas distintas de pedirle algo a la IA

No son técnicas que uses todas a la vez. Cada una resuelve un problema puntual: que la respuesta salga genérica, que el razonamiento tenga errores, que necesites que la IA use una herramienta real en lugar de inventar un dato. Toca cada una para ver el ejemplo.

Role Prompting (juego de roles) ＋

Para qué sirve

Le asignas a Claude un rol profesional concreto para que responda con ese criterio y ese vocabulario, en lugar de una respuesta genérica.

Ejemplo

«Actúa como un abogado tributarista colombiano. Revisa este contrato de prestación de servicios y señala los riesgos fiscales.»

Persona Prompting ＋

Para qué sirve

Vas más allá del rol y definís una personalidad completa: cómo habla, qué tono usa, qué evita. Sirve cuando necesitas una voz consistente en todo un proyecto.

Ejemplo

«Responde como una mentora de negocios directa, sin rodeos, que explica con ejemplos reales y nunca usa jerga técnica sin traducirla.»

Zero-shot Prompting ＋

Para qué sirve

Le pides la tarea directamente, sin darle ningún ejemplo previo de cómo hacerla. Funciona bien para tareas simples o poco ambiguas.

Ejemplo

«Escribe un correo de seguimiento para un cliente que no respondió en una semana.»

One-shot Prompting ＋

Para qué sirve

Le muestras un solo ejemplo de lo que esperas antes de pedirle la tarea, para fijar el formato o el tono.

Ejemplo

«Así es como armo un correo de bienvenida: [ejemplo]. Escribí uno igual para un cliente nuevo de consultoría.»

Few-shot Prompting ＋

Para qué sirve

Le das varios ejemplos seguidos para que detecte el patrón exacto — extensión, tono, estructura — y lo repita.

Ejemplo

«Aquí van tres captions de Instagram que ya usamos: [1] [2] [3]. Escribí uno más para el mismo lanzamiento, con el mismo tono.»

Chain of Thought (CoT) ＋

Para qué sirve

Le pides que razone en voz alta, paso a paso, antes de dar la respuesta final. Mejora la precisión en tareas que requieren varios pasos lógicos.

Ejemplo

«Antes de responder, piensa paso a paso: primero identifica el problema, después las causas posibles, y al final la solución.»

Tree of Thoughts (ToT) ＋

Para qué sirve

En vez de seguir un solo camino de razonamiento, explora varias alternativas en paralelo, las compara, y elige la mejor.

Ejemplo

«Genera tres estrategias distintas para lanzar esta campaña, evalúa ventajas y riesgos de cada una, y quédate con la más sólida.»

Self-Consistency ＋

Para qué sirve

Le pides que resuelva lo mismo por caminos distintos y compare los resultados, para quedarse con la respuesta que se repite. Reduce errores en cálculos o razonamientos complejos.

Ejemplo

«Resuelve este cálculo de tres formas distintas y decime cuál respuesta coincide en las tres.»

ReAct (razonar + actuar) ＋

Para qué sirve

Combina el razonamiento con el uso de herramientas reales — buscar en la web, consultar un archivo, correr una fórmula — en lugar de responder solo con lo que ya sabe.

Ejemplo

«Busca el valor actual del dólar y calcula cuánto pagaría en dólares un cliente en Panamá por este servicio de $3.500.000 COP.»

Chain of Verification (CoVe) ＋

Para qué sirve

Antes de entregar la respuesta, Claude revisa cada dato o afirmación contra la fuente y corrige lo que encuentre mal. Útil cuando la exactitud importa más que la velocidad.

Ejemplo

«Antes de entregarme el informe final, revisa cada cifra contra el archivo original y corregí cualquier inconsistencia.»

Skeleton of Thought (SoT) ＋

Para qué sirve

Primero pides solo el esqueleto — los títulos o los puntos principales — y esperas tu aprobación antes de desarrollar cada parte.

Ejemplo

«Dame primero el esquema del informe, solo los títulos de cada sección. Espera mi aprobación antes de desarrollarlo.»

Step-back Prompting ＋

Para qué sirve

Antes de resolver el caso puntual, le pides que explique el principio general detrás. Ayuda cuando el tema es nuevo o el contexto es ambiguo.

Ejemplo

«Antes de armar la campaña para este cliente, explica primero cómo funciona en general una campaña de Meta Ads B2B.»

Meta Prompting ＋

Para qué sirve

Le pides a Claude que mejore, corrija o diseñe un prompt — usas la IA para escribir mejores instrucciones para la misma IA.

Ejemplo

«Mejora este prompt para que la respuesta sea más específica y deje de sonar genérica.»

Socratic Prompting ＋

Para qué sirve

En vez de pedirle una respuesta directa, le pides que primero te haga preguntas para entender bien el problema antes de proponer algo.

Ejemplo

«Antes de darme una solución, hacéme las preguntas que necesites para entender el problema completo.»

Knowledge Elicitation ＋

Para qué sirve

Usas a Claude para extraer conocimiento que tienes en la cabeza pero no está escrito, a través de una serie de preguntas guiadas.

Ejemplo

«Hacéme preguntas una por una para armar el perfil de mi cliente ideal, a partir de lo que sé de mis clientes actuales.»

Prompt Chaining ＋

Para qué sirve

Divide una tarea grande en varios prompts encadenados, donde la salida de uno alimenta al siguiente.

Ejemplo

«Primero resumí este documento en diez líneas. Con ese resumen, arma una presentación de cinco slides.»

Contextual Prompting ＋

Para qué sirve

Le entregas documentos, datos o contexto de fondo antes de hacer la petición, para que la respuesta se ajuste a esa realidad y no a un caso genérico.

Ejemplo

«Aquí está el brief del cliente [adjunto]. Con esa información, escribí el guion del video de treinta segundos.»

09 · Antes de construir

Qué es un PRD y qué elementos tiene que tener

Un PRD (Product Requirements Document, o documento de requerimientos de producto) es el texto donde definís qué vas a construir antes de escribir una sola línea de código o de pedirle a la IA que te genere la app. Marca cada punto a medida que lo vayas resolviendo — sirve como checklist real, no solo como lectura.

Antes del PRD: pensamiento sistemático

Es la capacidad de entender cómo se conectan las distintas partes de un sistema entre sí, en lugar de mirar cada elemento por separado. Cuando cambias una pieza, cambia el comportamiento de todo el conjunto — por eso conviene responder esto antes de escribir el documento:

1. ¿Qué problema estoy resolviendo?
2. ¿Quién es el usuario?
3. ¿De dónde sale la información y cómo se conecta? Flujos, procesos, dependencias.
4. ¿Qué funcionalidades y campos necesita la app? Piensa en el MVP.
5. ¿Qué decisión sigue dependiendo de los humanos?
6. Base de datos, seguridad y gobierno de la información.

El documento maestro: siete elementos

0 de 7 resueltos

1¿Qué problema resuelve?

La razón de ser de la app. Si no puedes responder esto en una frase, todavía no estás listo para diseñarla.

2¿Quién es el usuario?

Quién la va a usar de verdad — no "todo el mundo", sino el perfil concreto con sus limitaciones y su nivel técnico.

3Proceso

Cómo se resuelve hoy ese problema, con o sin la app, paso por paso. Ahí salen los atajos que la app tiene que replicar.

4Qué información necesita

Qué datos tiene que pedir, recibir o consultar la app para funcionar: formularios, archivos, conexiones a otras herramientas.

5Qué se hará con la información

Si se guarda, se procesa, se cruza con otra fuente, se muestra tal cual. Define si necesitas base de datos o alcanza con mostrar algo en pantalla.

6Qué funcionalidades tendrá la app

La lista concreta de lo que el usuario puede hacer dentro de la app — no lo que "sería lindo tener", sino lo que necesita el primer lanzamiento.

7Cómo es la experiencia de usuario

La secuencia de pantallas que recorre alguien de principio a fin, y qué pasa en los casos donde algo sale mal o falta información.

10 · Anatomía técnica

De qué está hecha una app, en el orden en que se construye

Nueve piezas, en el orden lógico en que se arman una detrás de la otra. Sirve para entender qué pieza falta cuando algo no funciona.

1
Frontend

Lo que ve y toca el usuario. Puede ser una página web completa o un mini artefacto embebido en el chat.

2
Backend

La lógica que decide qué pasa con cada acción del usuario, sin mostrarse nunca en pantalla.

3
Base de datos

Donde vive la información de forma permanente, organizada en filas y columnas, para que sobreviva a un cierre de sesión.

4
API / MCP / Composio

El punto donde la app empieza a hablar con servicios externos: Gmail, un CRM, cualquier herramienta de afuera.

11 · Automatización sin código

Qué es un script de Google

Google Apps Script es la plataforma de Google para escribir pequeños programas en JavaScript directamente dentro de Sheets, Docs, Gmail o Calendar, sin instalar nada y sin salir del navegador. Se abre desde el mismo Google Sheets — menú Extensiones → Apps Script — y corre en los servidores de Google, no en tu computador.

Sirve para automatizar cosas puntuales que Make o Zapier resolverían con varios pasos: mandar un correo automático cuando cambia una celda, generar un documento a partir de una fila de la hoja, mover datos entre pestañas según una condición. Es la opción cuando la automatización vive completamente dentro del mundo de Google y no necesita conectar apps externas.

El paso a paso para conectarlo a tu app+

Así se ve el flujo completo cuando lo usas para conectar una hoja de cálculo a una aplicación:

  1. Abrí tu Google Sheet — funciona con cualquier archivo, siempre que no tenga celdas combinadas.
  2. Anda a Extensiones → Apps Script. Se abre un lienzo en blanco listo para recibir código.
  3. Pedile a Claude el código de Apps Script para lo que necesitas — copialo y pegalo ahí.
  4. Haz clic en Implementar (el botón azul) y elegí el tipo App Web.
  5. En descripción pon algo como "V1", y en acceso elegí Cualquiera.
  6. Obtén la URL de la app web — esa es la que conectas en tu aplicación.
